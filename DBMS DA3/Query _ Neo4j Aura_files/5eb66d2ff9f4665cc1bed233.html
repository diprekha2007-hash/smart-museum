newMultiple databases: new options for backup, restore, and pause
AuraDB Instances with multiple databases now have three more ways to manage data and costs! Create Restore Point Take a backup of every database in the instance at once, or back up a single database on its own. Restore instance Restore all databases in the instance. Provide a target timestamp, and the latest backup before that time is used to restore each database. For details on Create Restore Point and Restore instance , See Docs . Pause and Resume Pause an instance to save cost when you don’t need it running, then resume when you’re ready. Pausing stops all databases in the instance, and resuming brings them all back to running.
newNode embeddings in one line: new gds.embedding endpoints for Aura Graph Analytics (preview)
Getting embeddings for your graph no longer means choosing an algorithm or tuning hyperparameters. The GDS Python client now includes two new preview endpoints, available only on Aura Graph Analytics : gds.embedding.create , which generates node embeddings with sensible defaults, and gds.embedding.train , which trains a model on your node properties and known classes. Use it to: Get node embeddings without picking a model, tuning parameters, or knowing graph ML Power similarity search, clustering, classification, and recommendations from the resulting vectors Train an embedding model on nodes you have already classified, such as accounts marked by risk level, to get embeddings tuned to that task, and store the model to reuse it in later sessions How to use it 🛠️ create adds the embeddings to your in-memory graph as a node property ( embedding by default). From there, they are yours to use: stream them into pandas, feed them to other algorithms in the same session, or write them back to your database. gds.embedding.create(G) That is the whole call: with no encoder specified, it runs FastRP with sensible settings chosen for you. For more control, you can set options such as embedding_dimension or random_seed . When the default isn't enough, gds.embedding.train trains a model that works like any other trained model in Aura Graph Analytics: pass its name to create , and optionally store it with gds.model.store to reuse it from later sessions through your project's model catalog . Both endpoints are in preview and may change as we gather feedback. They require GDS Python client 2.2 or later. See the Embeddings API docs , and let us know what you think.
newLarger 5TB Adjustable storage now available on Azure!
AuraDB Business Critical and Virtual Dedicated Cloud customers running on Azure can now configure up to 5TB of storage as standard, directly through the Aura Console or Aura API. Eligible customers can now provision higher storage capacities for both new and existing AuraDB Business Critical and Virtual Dedicated Cloud instances on Azure, within supported memory-to-storage ratios, for example: 192GB instances now support up to ~3TB of storage 256GB instances now support up to ~4TB of storage 384GB and 512GB instances now support up to ~5TB of storage Building on the adjustable storage capabilities previously introduced, this enhancement gives customers: Even greater flexibility: scale storage based on workload needs without increasing compute Improved cost efficiency: avoid additional compute costs when only more storage is required A smoother experience: configure storage directly without manual processes, custom workarounds, or support requests For more information on this feature, please read our documentation.
